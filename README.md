# راهنمای راه‌اندازی بات روبیکای AXEL

این پوشه (`bot/`) کاملاً مستقل از پروژه‌ی Cloudflare است و روی سیستم شخصی یا گوشی
(Pydroid) شما اجرا می‌شود. دیتابیس اصلی (D1) و همه‌ی منطق سفارش همچنان در Cloudflare
Worker (`api`) است؛ این بات فقط پل ارتباطی بین روبیکا و آن API است.

## ۱. پیش‌نیازها

- Python 3.9 یا بالاتر (روی گوشی: Pydroid 3)
- کتابخانه‌ی `rubka` نسخه‌ای که از کانال `@rubka_Library` دریافت کرده‌اید (نسخه‌ای که
  این بات با آن تست شده: **۷.۲.۵**)
- توکن بات روبیکا (از قبل دارید)

## ۲. نصب

```bash
cd bot
pip install -r requirements.txt
```

اگر pip نسخه‌ی متفاوتی از rubka نصب کرد (نه همان نسخه‌ی کانال)، حتماً قبل از اجرای
واقعی، اسکریپت `verify/inspect_rubka.py` را اجرا کنید:

```bash
python verify/inspect_rubka.py
```

اگر خروجی هرکدام از متدها با آنچه در `handlers.py`/`outbox_worker.py` استفاده شده
فرق داشت، اول کد را با آن نسخه هماهنگ کنید — هرگز بدون این بررسی به‌روزرسانی نکنید
(دقیقاً طبق قانونی که خودتان در مشخصات پروژه گذاشتید).

## ۳. تنظیمات

```bash
cp .env.example .env
```

سپس مقادیر زیر را در `.env` پر کنید:

| متغیر | توضیح |
|---|---|
| `RUBIKA_TOKEN` | توکن بات روبیکای شما |
| `AXEL_API_BASE` | آدرس کامل API Worker + `/api`، مثل `https://axel-api.xxx.workers.dev/api` |
| `BOT_SECRET` | باید **دقیقاً** همان مقداری باشد که در `api/wrangler.jsonc` برای `BOT_SECRET` گذاشته‌اید (یا با `wrangler secret put BOT_SECRET` تنظیم کرده‌اید) |
| `SHOP_URL` | آدرس فروشگاه، برای نمایش در پیام خوش‌آمدگویی |

⚠️ **رمز ثبت‌نام ادمین (`ADMIN_ENROLL_SECRET`) در فایل `.env` بات قرار نمی‌گیرد** —
این رمز فقط سمت Cloudflare (در `api/wrangler.jsonc` یا با `wrangler secret put
ADMIN_ENROLL_SECRET`) تنظیم می‌شود. برای ثبت خودتان به‌عنوان ادمین، کافی است همان
متن رمز را مستقیماً در پیوی بات (به بات، نه به کسی دیگر) ارسال کنید — بات آن را به
API می‌فرستد و اگر درست باشد (و هنوز به سقف ۲ ادمین نرسیده باشیم)، شما ثبت می‌شوید.

از یک رمز بسیار بلند و تصادفی استفاده کنید، مثلاً با این دستور در ترمینال یک رمز
امن بسازید:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

همین رشته را هم در `wrangler.jsonc` (یا `wrangler secret put`) و هم فقط در ذهن خودتان
(برای ارسال به بات) نگه دارید — در کد یا گیت‌هاب ذخیره‌اش نکنید.

## ۴. اجرا

```bash
python main.py
```

بات به‌صورت پیوسته پیام‌های روبیکا را Poll می‌کند و هم‌زمان یک ترد پس‌زمینه صف
پیام‌های در انتظار (`bot_outbox`) را هر ۳ ثانیه بررسی و ارسال می‌کند. برای توقف،
`Ctrl+C` بزنید.

روی گوشی (Pydroid 3): همین فایل `main.py` را باز و اجرا کنید؛ Pydroid باید در پس‌زمینه
فعال بماند (تنظیمات بهینه‌سازی باتری اندروید را برای Pydroid غیرفعال کنید تا سیستم آن
را نکشد).

## ۵. مراحل اولیه بعد از اولین اجرا

1. با اکانت شخصی خودتان (هرکدام از ۲ ادمین) به بات پیام `/start` بدهید.
2. همان رمز ثبت‌نام ادمین را در پیوی بات ارسال کنید تا به‌عنوان ادمین ثبت شوید.
3. دستور زیر را برای تنظیم شماره کارت پرداخت ارسال کنید:
   ```
   /setcard 6037-xxxx-xxxx-xxxx
   ```
4. حالا سیستم آماده‌ی دریافت سفارش واقعی از سایت است.

## ۶. اجرای هم‌زمان روی چند دستگاه

طبق آنچه گفتید ممکن است بات هم روی سیستم و هم روی گوشی اجرا شود — **این کار را
هم‌زمان انجام ندهید**. کتابخانه‌ی rubka با Long-Polling (`get_updates`) کار می‌کند؛
اگر دو نمونه از بات هم‌زمان اجرا شوند، هر دو برای دریافت یک پیام رقابت می‌کنند و
پردازش تکراری/گم‌شدن پیام محتمل می‌شود. همیشه فقط **یک نمونه** از `main.py` را در
یک لحظه اجرا کنید؛ برای جابه‌جایی بین گوشی و سیستم، ابتدا نمونه‌ی قبلی را متوقف کنید.
(چون همه‌ی وضعیت مهم در Cloudflare D1 است، جابه‌جایی کاملاً بی‌خطر است — فقط دو نمونه
را هم‌زمان روشن نگذارید.)

## ۷. عیب‌یابی

- **بات پیام نمی‌فرستد ولی خطایی هم نیست**: لاگ ترد `axel_bot.outbox` را چک کنید؛
  اگر `ادمینی ثبت نشده` می‌بینید یعنی هنوز هیچ ادمینی ثبت‌نام نکرده (مرحله ۵.۲).
- **خطای 401 از API**: مقدار `BOT_SECRET` در `.env` بات با مقدار `wrangler.jsonc`
  یکی نیست.
- **`get_username` مشکل داشت**: این تابع در محیط شما تست نشده (فقط امضایش تأیید شده
  بود، نه دقیقاً ساختار مقدار بازگشتی‌اش). نام‌کاربری فقط برای نمایش استفاده می‌شود و
  هیچ‌جای منطق اصلی به آن وابسته نیست؛ اگر خطا داد، `helpers.safe_get_username` آن
  را بی‌صدا نادیده می‌گیرد و کار متوقف نمی‌شود.
